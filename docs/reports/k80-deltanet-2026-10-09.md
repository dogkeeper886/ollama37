# Gated DeltaNet decode step as one op on the K80 (#571)

| | |
|---|---|
| Build | branch `study-571-k80-deltanet` on `ec50153b` (#563, #565, #567 merged), version 2.3.3-571 |
| Baseline | CI run 37808206105 (#567's code, the same kernels as `main`), same host |
| Host | 4 × Tesla K80 dies (sm_37), CUDA 11.4, driver 470.256.02; lab runs on die 1 |
| Measured | 2026-10-09 |

The qwen35 family (qwen3.5, qwen3.6, qwen3.8, ornith) is hybrid: most layers are Gated DeltaNet layers
that carry a recurrent state, 32 heads × 128 × 128 floats (~2 MB) per layer. At decode,
`deltaNetAutoregressive` updated it with generic ops: two permuted `CONT`s, broadcast `MUL`s, `REPEAT`,
`ADD`, `SUM_ROWS` and a `CPY` back to the cache, about 10 passes over the state and dozens of launches per
layer. The new op `ggml_gated_delta_step` (CPU and CUDA) does the whole step at once; the Go backend uses
it only when every GPU is CUDA below cc 5.0, and every other card keeps today's op chain.

## Where the time went

A lab-only per-op GPU timer (local branch `lab-opprof`, not merged) on `qwen3.6:35b`, the repo's
`speech-rewrite` prompt, 300 decode tokens: small elementwise and copy ops took about half of each
~95 ms token (with the timer on), `CONT` alone ~18 ms (~300 calls of ~60 µs). A replica of the DeltaNet
step for 30 layers took 30 ms, ~37 % of the token; 63 % of that was `cpy_flt`, the permuted copies of
the 2 MB state at ~200 µs each. Dense models don't have this cost: `llama3.1:8b`'s largest non-matmul
op is softmax at 1.3 %.

## The op

Per head, with q and k L2-normalized (as `ggml_l2_norm`), q scaled, β = sigmoid(β) and g = exp(g):

```
S = g·S;   delta = β·(v − S k);   S = S + delta kᵀ;   out = S q
```

- **CUDA:** one block per (head, sequence), one thread per value index. The state is stored with the
  value index fastest, so each step of the inner loop reads one contiguous row across the block; each
  thread keeps its column of 128 values in registers and reads and writes the state once.
- **CPU:** a plain loop over (sequence, head); it is the fallback and the reference.
- **Go:** `ml.Tensor.GatedDeltaStep` returns the op when the backend's GPUs are all Kepler and nil
  otherwise; `deltaNetAutoregressive` keeps its op chain on nil. The chunked prefill path is unchanged and
  shares the state layout.

## Lab, one die

30 layers of `qwen3.6:35b`'s shape, against a double-precision reference of the recurrence:

| 30 layers, one token | Time | Output error | State error |
|---|--:|--:|--:|
| Today's op chain | 30.0 ms | 1.2e-7 | 1.2e-7 |
| `ggml_gated_delta_step`, CUDA | **0.93 ms** | 3.0e-7 | 1.0e-7 |
| `ggml_gated_delta_step`, CPU | 12.7 ms | 3.0e-7 | 1.2e-7 |

`ggml_rwkv_wkv7` was the alternative: the same recurrence fits it, but it stores the state transposed and
its threads each walk their own 512-byte row, which the K80 reads poorly.

Pipeline [37870785444](https://github.com/dogkeeper886/ollama37/actions/runs/37870785444): build,
deploy and canary pass; the models test judges all 29 replies across 22 models, 0 failed.

`test-throughput.yml`, the standard `speech-rewrite` run on all 25 models: branch run
[37876494396](https://github.com/dogkeeper886/ollama37/actions/runs/37876494396) against
[37808206105](https://github.com/dogkeeper886/ollama37/actions/runs/37808206105). All 25 replies pass the

- **The qwen35 family gains +25.4 % on average.** The MoE members gain most (+34–36 %): their weight
  reads per token are small, so the DeltaNet step was a larger share. The 27B members have dense
  feed-forward layers, so it was a smaller share (+13 %).
- **The other 18 models never run the op;** their −3 % to +2 % is run-to-run noise.
- **Prefill: within ±2 %.** Prefill uses the chunked path, which this change leaves alone.

## Long context on a real speech: crash check

`test-throughput.yml` with `prompt=farewell-summary` (~7,300 tokens, `num_ctx` 12288) on all 25 models,
run [37880517403](https://github.com/dogkeeper886/ollama37/actions/runs/37880517403). The DeltaNet state
carries the whole context, so this checks the op at long context.

| Check | Result |
|---|---|
| Runner crashes or errors | none |
| Spill to CPU | none; every model 100 % on GPU |
| Broken text (judge) | none; all 25 judged not broken |
| Loops | none; no 3-word phrase repeats more than twice |
| Window | only `gemma4:12b` fills it, its own tokenizer bug (#568), as on `main` |

- **The qwen35 family decodes 22–39 % faster at long context too,** against the #565 run
  [37780450973](https://github.com/dogkeeper886/ollama37/actions/runs/37780450973): `qwen3.6:35b`
  10.91 → 15.16, `ornith-1.5:35b` 10.99 → 15.26, `qwen3.5:9b` 10.90 → 14.06, `qwen3.6:27b` 3.52 → 4.31.
- **Replies:** `qwen3.5:9b`, `qwen3.6:27b`, `qwen3.6:35b` and `qwen3.8:27b` are word for word identical
  to the baseline's. The ornith replies differ in wording; they still name the Farewell Address and plan
  the summary in order. Since the baseline, #567 also changed the q6_K output head, which picks the first
  token after the prompt.
- **One slow outlier:** `llama3.1:8b` decoded at 8.96 tok/s here against 12.56 in the baseline. The op
  never runs for llama, its die ran at a normal 716 MHz, and the same request on the host's #571 build
  decodes at 13.57 and 13.52 tok/s, so it was a one-off slow run.

## Limits

- **One run per row** in CI.
- **Decode only, batch 1 per sequence;** the chunked prefill path still uses generic ops.
- **The op is new to this fork's ggml:** an upstream sync (`Makefile.sync`) would overwrite its edits to
  `ggml.h`, `ggml.c` and the CPU backend and delete `gated-delta.cu`, so a sync must carry it over.
