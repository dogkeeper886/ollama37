## 2. New Models — Gemma 4 & Qwen 3.5

> I ported Gemma 4 and Qwen 3.5 in this release. What I'm really interested in is how they perform compared to GPT-OSS and Gemma 3 — models that were already working in earlier versions.
>
> Now, one thing about these models — especially the 27B ones — is that they usually can't load in limited GPU environments. You need a lot of VRAM. But with K80 multi-GPU, we can split them across GPUs and actually run them.

**Screen:** Show the release page, scroll through the new model section.

> Let me show you the benchmark numbers. I have a throughput benchmark that runs in GitHub Actions on the actual K80 hardware.

**Screen:** Navigate to [benchmark CI run](https://github.com/dogkeeper886/ollama37/actions/runs/24328063868). Show the summary table.

> Let's look at memory first.

### Memory Usage

> Gemma 4 comes in two sizes. The small one, gemma4:e4b, fits on a single GPU — it uses about 9.8 GiB. The big one, gemma4:26b, needs two GPUs — about 9.3 GiB on each.
>
> Qwen 3.5 is similar. The 9B fits on one GPU at 7.5 GiB. The 27B needs two GPUs — about 10.6 GiB each.
>
> For comparison, gemma3:27b also needs two GPUs at about 10 GiB each. And gpt-oss:20b uses two GPUs at about 7.4 GiB each.

| Model | GPUs | VRAM per GPU |
|-------|------|--------------|
| gemma4:e4b | 1 | 9796 MiB |
| gemma4:26b | 2 | 9295 + 9288 MiB |
| qwen3.5:9b | 1 | 7529 MiB |
| qwen3.5:27b | 2 | 10636 + 10514 MiB |
| gemma3:4b | 1 | 4785 MiB |
| gemma3:27b | 2 | 10004 + 9912 MiB |
| gpt-oss:20b | 2 | 7382 + 7556 MiB |

### Performance

> Now the interesting part — speed.
>
> Gemma4:26b gets 42 tokens per second on prompt and 12 tokens per second on generation. Compare that to gemma3:27b which gets 8.6 prompt and 3 generation. That's roughly 4 times faster at the same parameter class. That's a big generational improvement.
>
> The smaller gemma4:e4b gets about 65 prompt and 13 generation — very close to gemma3:4b which gets 68 and 15. Similar speed, but gemma4 uses more VRAM.
>
> Qwen3.5:27b gets about 8.6 prompt and 2.6 generation — similar to gemma3:27b. The 9B version is faster at 31 prompt and 7.7 generation.
>
> And gpt-oss:20b is still the fastest at prompt eval — 129 tokens per second. It's hard to beat.

| Model | Prompt tok/s | Gen tok/s |
|-------|-------------|-----------|
| gpt-oss:20b | 128.96 | 14.80 |
| gemma4:e4b | 64.88 | 13.12 |
| gemma3:4b | 68.48 | 15.24 |
| **gemma4:26b** | **42.64** | **12.09** |
| qwen3.5:9b | 31.17 | 7.66 |
| **gemma3:27b** | **8.62** | **3.02** |
| qwen3.5:27b | 8.59 | 2.61 |

## 4. Live Demo — Dify Chat + Grafana GPU Monitoring

> Let me show you what it actually looks like when you run these models. I have a Dify chat interface connected to ollama37, and a Grafana dashboard monitoring my GPUs in real time.

**Screen:** Split or switch between Dify chat and Grafana dashboard.

### Grafana panels to show:
- **GPU VRAM usage** — watch it spike when model loads
- **GPU temperature** — K80 thermals under load
- **Generation speed** — tokens per second in real time

### Demo flow:

1. **Start idle** — show Grafana with GPUs at baseline (low VRAM, cool temps)

2. **Load a model via Dify** — send a prompt
   - Watch VRAM fill across GPUs on Grafana
   - Temperature starts rising
   - Generation speed visible as response streams in

3. **Point out the numbers**
   > You can see GPU 0 and GPU 1 are now using about 9-10 GiB each. Temperature is climbing. And the response is coming in at about 12 tokens per second — matches what we saw in the benchmark.

4. **Try another model** (optional — compare a smaller/faster model)

5. **Model unload** — show VRAM dropping back down on Grafana
