## 3. Other Models — FunctionGemma & Ministral-3

> Those are the main models. But there are two smaller ones worth mentioning — they fill very different niches.
>
> FunctionGemma is tiny — 270 million parameters, half a gig of VRAM. I ported it because I was curious whether something that small could handle tool calling. Turns out it's too small to really understand the request. If you've found a good use case for this model, let me know in the comments.
>
> Ministral-3 was actually a user request — someone opened an issue because the model wouldn't load at all. Turned out the template was missing a function. But fixing that was just the start.
>
> When I first loaded it, this 3 gig model was eating 13 gigs of VRAM. That makes no sense. After tracing it, I found the vision encoder was reserving memory for a 2048 by 2048 image — over 8 gigs just for that buffer. On a K80 without flash attention, that's a full GPU wasted on a worst-case reservation. I capped it at 512 by 512 for K80s, and the model dropped to about 3.5 gigs — fits on a single GPU.
>
> The other problem was ghost GPU allocations. Some models were spreading across all 4 GPUs even when they only needed one. A 3 gig model on 2 GPUs, a 6 gig model touching all 4. That's fixed now too.
>
> After all that, Ministral-3 generates at about 17 tokens per second — tied with GPT-OSS for the fastest in the lineup.

| Model | Prompt tok/s | Gen tok/s | VRAM |
|-------|-------------|-----------|------|
| ministral-3:3b | 1155.91 | 17.29 | 3466 MiB |
| functiongemma:270m | — | — | 517 MiB |

## 4. Live Demo — Dify Chat + Grafana GPU Monitoring

> So those are the benchmarks. But what does it actually look like running? Here's a Dify chat interface connected to ollama37, and a Grafana dashboard monitoring the GPUs in real time.

**Screen:** Split-screen — Dify chat on the left, Grafana dashboard on the right.

### Grafana panels to show:
- **GPU VRAM usage** — watch it spike when model loads
- **GPU temperature** — K80 thermals under load
- **Generation speed** — tokens per second in real time

### Demo flow:

1. **Start idle** — show Grafana with GPUs at baseline (low VRAM, cool temps)

   > Right now the GPUs are idle. VRAM is almost empty, temperatures are low.

2. **Load gemma4:26b via Dify** — send prompt: "Explain quantum entanglement in simple terms"

   > I'll send a prompt to Gemma 4 27B. Watch the Grafana panel on the right — you should see VRAM spike across two GPUs.

   *(While model loads:)*

   > It's loading the model now — this takes a few seconds the first time. You can see VRAM filling up on GPU 0 and GPU 1.

3. **Point out the numbers as response streams in**

   > There it is — both GPUs are using about 9 to 10 gigs each. Temperature is climbing. And the response is streaming in at about 12 tokens per second — that matches what we saw in the benchmark.

4. **Model unload** — show VRAM dropping back down on Grafana

   > And when the model unloads, you can see the VRAM drop back down.
